Casos de Prueba - Proyecto PrestaFácil / Finanpanorama

1. Introducción

Este documento define los casos de prueba y el ambiente de pruebas para la aplicación PrestaFácil, un sistema de gestión de préstamos personales desarrollado en Node.js, Express y MySQL. La aplicación permite a los clientes registrar solicitudes de crédito, firmar digitalmente el pagaré, y recibir notificaciones de confirmación por correo electrónico. Además, los administradores cuentan con un panel protegido por autenticación para consultar, actualizar y gestionar las solicitudes de los clientes.

Descripción de la historia La historia de usuario describe la funcionalidad de registrar una solicitud de crédito (datos personales, monto solicitado), firmar digitalmente el pagaré, recibir un correo de confirmación, y permitir que un administrador autenticado consulte, actualice o elimine las solicitudes desde un panel privado.

3. Fuera de Alcance

  • Pruebas de rendimiento: No se realizará un análisis exhaustivo de la capacidad del sistema para manejar cargas pesadas, múltiples usuarios simultáneos o estrés de alta carga, ya que el proyecto se encuentra en fase académica/piloto con bajo volumen de tráfico.
  • Pruebas de seguridad avanzadas: Las pruebas de penetración profesional (pentesting) y el escaneo exhaustivo de vulnerabilidades no serán cubiertas en esta fase; solo se validan controles básicos de autenticación y validación de entradas.

4. Tipos de prueba / Estrategia (Cómo ejecutar las pruebas)

  • Pruebas unitarias automatizadas (Jest): Se probó la lógica de los controladores de autenticación y de clientes de forma aislada, usando mocks para simular la base de datos y los servicios externos.
  • Pruebas funcionales / manuales basadas en historias de usuario: Se ejecutaron peticiones reales a la API (login, registro de clientes, firma digital, CRUD) usando PowerShell/Postman, verificando los códigos de respuesta HTTP y los datos devueltos.
  • Cross-browser testing (Múltiples navegadores): Se probarán las vistas públicas (formulario de solicitud, panel admin) en navegadores como Chrome, Firefox y Edge.
  • Cross mobile testing (Emulado con Chrome): Se emulará la aplicación en dispositivos móviles mediante las herramientas de desarrollo de Chrome, dado que el formulario de solicitud debe ser accesible desde celular.

7. Riesgos

Riesgo Probabilidad Impacto Mitigación
Incompatibilidad con navegadores o dispositivos móviles en el formulario de solicitud Media Medio Realizar pruebas de compatibilidad en múltiples dispositivos y navegadores antes del despliegue.
Fallas en la integración con el servicio de correo (Nodemailer/Gmail) Baja Alto Validar el envío real de correos de confirmación y manejar errores sin interrumpir el registro del cliente.
Fallas en la subida de la firma digital a Cloudinary Baja Alto Implementar un plan B que guarde la firma en Base64 en la base de datos si Cloudinary falla.
Faltas en la validación de datos de entrada del cliente (campos vacíos, documentos duplicados) Alta Medio Asegurar validación completa en el controlador antes de insertar en la base de datos (ya implementado y probado con Jest).
Caídas o latencia en la conexión a la base de datos MySQL Media Alto Monitorear el pool de conexiones y probar el comportamiento del sistema cuando MySQL no está disponible.
