1 Introducción

El presente informe describe el plan de trabajo técnico para el diseño, desarrollo e implementación de un Sistema de Gestión de Inventarios (SGI) orientado a controlar existencias, movimientos de productos, trazabilidad, reposición y generación de reportes operativos y estratégicos.

Se definen las fases del proyecto, la arquitectura tecnológica, herramientas de desarrollo, estrategias de control de versiones y un esquema de Integración Continua y Entrega Continua (CI/CD) que garantice calidad, trazabilidad y despliegue automatizado en los distintos entornos del sistema.

Este documento sirve como guía de referencia técnica para el equipo de desarrollo, gestores del proyecto y partes interesadas que requieran comprender el alcance, la arquitectura y los lineamientos de ejecución del SGI.
2 Objetivos del Proyecto
Objetivo General

Desarrollar un software web seguro, escalable y mantenible que permita administrar el inventario en tiempo real, brindando visibilidad completa del ciclo de vida de los productos dentro de la organización.

Objetivos Específicos
  • Centralizar el control de entradas, salidas y stock de productos en una sola plataforma.
  • Automatizar alertas de mínimos y reposición para evitar desabastecimiento.
  • Generar reportes analíticos operativos y estratégicos exportables.
  • Garantizar trazabilidad de cambios mediante una estrategia integral de versionamiento.
  • Implementar pruebas automáticas e integración continua que aseguren calidad del código en cada entrega.

4 Arquitectura Propuesta

Se adopta una arquitectura cliente-servidor de tres capas, separando claramente la presentación, la lógica de negocio y la persistencia de datos. El patrón estructural elegido es MVC (Model-View-Controller) complementado con una API RESTful para permitir consumo desde múltiples clientes.

Capa Componente Responsabilidad
Presentación Frontend (SPA) Interfaz de usuario, formularios, reportes visuales
Lógica de negocio Backend / API REST Reglas, validaciones, autenticación JWT, endpoints
Persistencia Base de datos relacional Almacenamiento de transacciones, stock, auditoría
Infraestructura Docker + Nginx Contenerización, reverse proxy, entornos replicables
Patrón elegido: MVC + API RESTful garantiza separación de responsabilidades, facilidad de mantenimiento y posibilidad de integrar con terceros mediante contratos de API bien definidos.

7 Estrategia de Versionamiento

Se utiliza Git como sistema de control de versiones distribuido, alojado en GitHub / GitLab / Bitbucket. Se adopta el flujo Git Flow simplificado:

RamaPropósitoProtección
mainCódigo en producción, estable y certificadoProtegida
developIntegración de nuevas funcionalidadesPR requerido
feature/*Desarrollo de funcionalidades individualesLibre
hotfix/*Correcciones urgentes en producciónRevisión
release/*Preparación de una nueva versiónQA aprobado
Convención de commits semánticos:
feat: nueva funcionalidad  |  fix: corrección de bug  |  docs: documentación  |  test: pruebas  |  refactor: refactorización
8 Integración Continua (CI/CD)
EtapaHerramientaDescripción
Trigger GitHub Actions / GitLab CI Activado en cada Push o Pull Request a develop/main
Lint & análisis ESLint / SonarQube Análisis estático de código y detección de vulnerabilidades
Pruebas automáticas Jest / Pytest Ejecución de suite de pruebas unitarias e integración
Build Docker Construcción de imagen Docker reproducible
Despliegue Docker Compose / K8s Deploy automático según el entorno destino
🧪 Entorno Dev

Despliegue inmediato con cada commit a develop. Tests rápidos, sin validación formal.

🔬 Entorno Staging

Espejo de producción. QA completo, smoke tests y validación de requisitos previos al release.

14 Conclusiones

El plan de trabajo técnico presentado en este informe define un enfoque integral, estructurado y orientado a la calidad para el desarrollo del Sistema de Gestión de Inventarios. Las siguientes reflexiones sintetizan los pilares fundamentales del proyecto:

🔀 Control de versiones como columna vertebral del proyecto

La adopción de Git Flow simplificado con commits semánticos, Pull Requests y revisiones de código garantiza trazabilidad completa de cada cambio realizado al sistema. Ninguna modificación al código fuente queda sin registro, facilitando auditorías, rollbacks y la colaboración entre equipos.

⚡ CI/CD como garantía de calidad continua

La implementación de pipelines de Integración y Entrega Continua mediante GitHub Actions o GitLab CI permite detectar errores de forma temprana, automatizar pruebas y garantizar que únicamente código probado y validado llegue a los entornos de producción. Esto reduce drásticamente el riesgo de regresiones e incidentes críticos.

🏗️ Arquitectura modular para escalabilidad futura

La arquitectura MVC de tres capas con API RESTful desacopla la interfaz de usuario de la lógica de negocio y la base de datos. Esta separación facilita el mantenimiento independiente de cada componente, permite cambiar tecnologías en capas específicas sin afectar el sistema completo y habilita la integración con servicios externos mediante contratos de API bien definidos.

🔒 Seguridad integrada desde el diseño

Al incorporar HTTPS, JWT, bcrypt y RBAC desde las fases tempranas del diseño, y no como un añadido posterior, el sistema adopta el principio de Security by Design. Esto reduce la superficie de ataque y facilita el cumplimiento de normativas de protección de datos.

🚀 Viabilidad y sostenibilidad del proyecto

La combinación de la metodología Scrum, un plan de trabajo realista de 13 semanas, tecnologías de mercado ampliamente soportadas (Node.js, React/Vue, PostgreSQL, Docker) y una estrategia de riesgos definida, confieren al proyecto una alta viabilidad técnica y garantías de sostenibilidad a largo plazo.

En conclusión: El presente plan no solo establece qué se construirá, sino cómo se construirá de forma responsable, trazable y con calidad asegurada. La adhesión a estándares modernos de ingeniería de software posiciona al SGI como una solución robusta, mantenible y lista para crecer con las necesidades de la organización.
